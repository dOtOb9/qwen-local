# Issue #4: Google Calendar連携の基盤(OAuth認可 + 予定参照)

- 日付: 2026-09-12
- ステータス: 実装完了(build確認済み)、PRは未作成(compare URLをIssueに投稿予定)

## 目的

「秘書のようなアプリにしたい」という方向性の一環として、Google Calendarの
読み取り専用連携(OAuth認可 + 直近7日の予定参照chat tool)を追加する。
予定の作成・変更は別Issueで扱うスコープ外。

## やったこと

- 既存の`gmail.rs`にGoogle OAuth 2.0 (Authorization Code + PKCE)の
  汎用ループバックフロー(`google_oauth_login`、scopeを引数で渡せる)が
  既に実装済みだったため、Calendar向けに新規のOAuthコマンドは作らず
  これを再利用する方針にした(Issue本文の「例: `start_google_oauth`」は
  あくまで例示だったため)。`refresh_access_token`を`pub(crate)`にして
  `calendar.rs`から共有した。
- `src-tauri/src/calendar.rs`を新設し、`list_calendar_events`
  Tauriコマンドを実装。`GET /calendars/primary/events`を
  `timeMin=今`〜`timeMax=7日後`、`singleEvents=true`、
  `orderBy=startTime`で叩き、予定のタイトル・開始/終了・場所を返す。
  日時計算に`chrono`クレートを新規追加した(標準ライブラリだけでは
  RFC3339のタイムゾーン付き日時計算が煩雑なため)。
- `src/lib/ollama.ts`に`check_calendar` chat toolを追加。
  `ToolContext.googleCalendarRefreshToken`が設定されている場合のみ
  ツール定義をOllamaに提示する(Rakuten/Gmail未設定時のフォールバックと
  同じパターン)。
- `src/components/SettingsDialog.tsx`に「Googleカレンダー」セクションを
  追加。Client ID/Secretは既存のGmail用の入力欄を共用しつつ、
  スコープ(`https://www.googleapis.com/auth/calendar`)が異なるため
  ログインボタン・refresh_tokenの保存先(`google_calendar_refresh_token`
  設定キー)はGmailとは独立させた(Googleのrefresh_tokenは同意時の
  スコープに紐づくため、Gmail用のrefresh_tokenを流用できない)。
- `src/App.tsx`で`google_calendar_refresh_token`設定を読み出し、
  `chatWithTools`の`ToolContext`に渡すよう配線した。
