# カメラVSLAMロボット工作

- 日付: 2026-09-10
- ステータス: 進行中

## 目的

qwen-localのハードウェア工作入門として、カメラベースのVSLAM(Visual SLAM)で
自律的に動くロボットを作る。Lidarはコストが高いため単眼カメラを採用。
点群解析ソフトの仕事の知見を、将来的に自前のVO/マッピングロジックへ活かす方向で進める。

## 方針: 構成

- **カメラ**: 単眼USB Webカメラ(最安構成。スケール不定の単眼VO/SLAMを自前実装/チューニングする前提)
- **計算分担**: ロボット側(Raspberry Pi)は撮影とWi-Fi送信のみ。VSLAM本体はPC(RTX4070)側で実行する。
  Wi-Fi越しにフレームをPCへストリーミングし、PCから走行コマンドを返す構成。
  qwen-localで既に構築済みのOllamaネットワーク越し呼び出し(`OLLAMA_ORIGINS`)の土台を流用できる。

```
[ロボット本体]                      [PC: RTX4070]
Raspberry Pi 4/5                    Ollama (qwen2.5)
 + USBカメラ                         + VSLAM処理 (pyslamなど)
 + モータードライバ(L298N等)          + Qwenによる自然言語/意味理解層
 + TTモーター×2 + シャーシキット
     │  Wi-Fi (MJPEG/UDP映像ストリーム)
     │  Wi-Fi (走行コマンド受信)
     └──────────────────────────────┘
```

## マイルストーン

1. **M1 組み立て**: シャーシ+モーター+Pi+カメラの配線、Pi単体でモーター制御スクリプトが動く
2. **M2 映像ストリーミング**: PiからPCへWi-Fi経由でカメラ映像をリアルタイム送信
3. **M3 VSLAM疎通**: PC側で受信映像に対し単眼VO/SLAM(`pyslam`など)を動かし、軌跡・自己位置を可視化
4. **M4 遠隔操縦**: PC→Piへ走行コマンドを送り、簡単なテレオペを実現
5. **M5(任意) Qwen連携**: 自然言語の指示をQwenで解釈してナビゲーション指令に変換、
   またはVSLAMで得た軌跡/マップに対する説明生成

## 派生: 部材調達アシスタント機能

工作のたびに部材をWeb検索するのが面倒という話から、調達を助ける機能のアイデアが出た。
検討の結果:

- ローカルのQwen自体にはインターネットアクセス能力がない(Ollamaはテキスト生成のみ)ため、
  「検索/取得」は外部の検索API(Google Custom Search / Bing / Braveなど)が別途必要。
  Qwenの役割は取得した検索結果を渡して比較・要約・推薦させる部分。
- 購入(カート投入・決済)の自動化はしない方針。ECサイトのbot購入は規約違反になりやすく、
  お金が絡む取り消しにくい操作なので、最終的な「買う」ボタンは人間が押す設計にする。
- 当初は`frontend-tauri`に検索API連携の調達アシスタント機能を追加する案を検討したが、
  APIキー取得や実装コストに見合わないと判断し**見送り**。代わりに、部材が必要になった
  都度Claudeに直接Web検索させて候補URLを出してもらう運用にする(アプリ化しない)。
